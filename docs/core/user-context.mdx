## Quick Start

Resolve user metadata at the proxy edge:

```ts theme={null}
import { fentaris, mcp, stdio } from "@fentaris/core";

const proxy = fentaris({
  servers: [
    mcp("analytics", {
      transport: stdio({ command: "node", args: ["./dist/analytics-server.js"] }),
      env: (user) => ({
        TENANT_ID: String(user.tenantId ?? "unknown"),
      }),
    }),
  ],
  user: (req) => ({
    id: req.headers["x-user-id"] as string | undefined,
    role: req.headers["x-user-role"],
    tenantId: req.headers["x-tenant-id"],
    traceId: req.headers["x-trace-id"],
  }),
});
```

## What It Contains

`UserContext` is a free-form object with an optional `id` field. Use it for metadata such as tenant IDs, roles, plans, and trace IDs.

```ts theme={null}
type UserContext = {
  id?: string;
  [key: string]: unknown;
};
```

## Where It Flows

- `fentaris(...)` resolves user context per request.
- Middleware and hooks receive `ctx.user`.
- `mcp(..., { env })` can inject per-user environment values into upstream transports.

## Middleware Example

```ts theme={null}
proxy.use(async (ctx, next) => {
  ctx.log.setTag("trace", ctx.user.traceId ?? "no-trace");

  if (ctx.user.plan !== "enterprise" && ctx.tool?.proxyName === "analytics__export") {
    return ctx.deny("Analytics export requires an enterprise plan.");
  }

  return next();
});
```

## Best Practices

- Keep user context small and stable.
- Normalize keys across services, for example `tenantId`, `role`, and `traceId`.
- Do not store secrets in `UserContext`.
- Log stable identifiers, not raw PII.
- Inject upstream secrets through credentials or `mcp(..., { env })`.

## Low-Level API

`McpProxy` and `McpServer` expose the same user context internally. New docs should prefer the high-level helpers unless documenting class behavior directly.
