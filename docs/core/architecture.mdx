# Architecture

> How Fentaris routes, aggregates, and serves MCP traffic

This page is kept for older links. The current concepts entrypoint is [Architecture](/concepts/architecture).

## Request Flow

```mermaid
flowchart LR
  Client[MCP Client] --> Proxy["fentaris(...) proxy"]
  Proxy --> Session[Streamable HTTP Session]
  Session --> ServerA["mcp(\"filesystem\")"]
  Session --> ServerB["mcp(\"github\")"]
```

1. An MCP client connects to the Fentaris endpoint.
2. Fentaris initializes an MCP session over HTTP.
3. The proxy lists tools from each `mcp(...)` server declaration.
4. Tool calls pass through policy, middleware, hooks, and logging.
5. The selected upstream transport forwards the call.

## Components

### `fentaris(...)`

Creates the proxy runtime and owns HTTP lifecycle, sessions, routing, policy, and observability.

### `mcp(...)`

Declares an upstream MCP server. The server name becomes the prefix for proxied tools, prompts, resources, and completion targets.

### Transport Helpers

Use `stdio(...)` for local MCP processes and `streamableHttp(...)` for remote native MCP HTTP endpoints.

## Low-Level API

`McpProxy`, `McpServer`, and transport classes remain available for advanced integrations. New docs and new applications should start with `fentaris(...)`, `mcp(...)`, and transport helpers.
