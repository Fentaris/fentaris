This tutorial walks through two upstream MCP servers, one proxy endpoint, middleware, and a server-scoped event hook.

## Quick Start

```ts theme={null}
import { fentaris, mcp, stdio } from "@fentaris/core";

const proxy = fentaris({
  servers: [
    mcp("filesystem", {
      displayName: "Filesystem",
      transport: stdio({
        command: "npx",
        args: ["-y", "@modelcontextprotocol/server-filesystem", "./demo-files"],
      }),
    }),
    mcp("diagnostics", {
      displayName: "Diagnostics",
      transport: stdio({
        command: "node",
        args: ["./dist/diagnostics-server.js"],
      }),
      env: (user) => ({
        USER_ID: user.id ?? "anonymous",
      }),
    }),
  ],
  port: 3000,
  path: "/mcp",
  name: "fentaris-proxy",
  version: "0.1.0",
});

await proxy.start();
```

## Add Middleware

Middleware runs before matching tool calls are forwarded upstream.

```ts theme={null}
proxy.use(async (ctx, next) => {
  ctx.log.info("tool-call", {
    server: ctx.server?.name,
    tool: ctx.tool?.name,
  });

  if (ctx.server?.name === "filesystem" && ctx.tool?.name === "delete") {
    return ctx.deny("Filesystem delete is disabled in this environment.");
  }

  return next();
});
```

## Add a Server Hook

```ts theme={null}
proxy.mcp("diagnostics").on("tool:success", async ({ ctx, durationMs }) => {
  ctx.log.info("diagnostics.tool.success", { durationMs });
});
```

## Connect a Client

From your MCP client, call the proxy at `http://localhost:3000/mcp`.

<Tip>
  Server-scoped routes such as `proxy.mcp("diagnostics")` keep tool-specific logic close to the upstream server it protects.
</Tip>

## What you built

- A single HTTP endpoint for multiple MCP servers.
- A middleware layer that enforces policy.
- Server-scoped logging for diagnostics calls.

## Low-Level API

`new McpProxy(...)`, `new McpServer(...)`, and `new StdioTransport(...)` remain available for advanced integrations. New applications should start with `fentaris(...)`, `mcp(...)`, and transport helpers.
