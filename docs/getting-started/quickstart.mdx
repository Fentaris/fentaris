This quickstart uses the Fentaris CLI to generate a ready-to-run local project with one remote HTTP upstream MCP server.

<Note>
  The generated `specification` upstream requires outbound network access. For a self-contained local-tool example, use [Team-governed proxy](/guides/team-governed-proxy).
</Note>

## CLI Setup

Install the CLI and generate a project:

```bash theme={null}
npm i -g @fentaris/cli
```

```bash theme={null}
fentaris init my-proxy
cd my-proxy
fentaris dev
```

For automation, pass the project name and scaffold choices explicitly:

```bash theme={null}
fentaris init my-proxy --non-interactive --package-manager pnpm --skip-install --skip-git
cd my-proxy
pnpm install
```

If you omit `--skip-install`, the package manager passed to `--package-manager` must be installed and available on `PATH`.

The proxy listens on `http://localhost:4000/mcp` by default. Generated projects read `port` and `path` from `fentaris.json`, so `fentaris dev` and `app.start()` stay aligned without hardcoding the endpoint in `src/index.ts`.

<Note>
  The generated app explicitly allows all upstream operations and does not configure authentication. Replace the development policy with API-key auth and an allow-list policy before exposing the proxy outside your machine.
</Note>

## Generated Project

`fentaris init` creates these files:

- `src/index.ts` with the runnable proxy example.
- `fentaris.json` for CLI project discovery and runtime `port`/`path` defaults.
- `.gitignore`, TypeScript config, and package scripts.

The generated `dev` and `start` scripts load an optional project `.env`. The file is ignored by Git. Fentaris creates `FENTARIS_AUTH_KEY` there only when the first local encrypted credential is written; projects without encrypted credentials do not need a key.

The generated `package.json` pins `@fentaris/core` to a caret range that matches the CLI release (currently `^3.0.0`). This makes local SDK/CLI integration tests deterministic — the app installs the same core the CLI was validated against instead of whatever happens to be `latest` on npm.

<Note>
  `fentaris init` initializes a git repository when git is available. Pass `--skip-git` to create only the project files.
</Note>

### Local development against the monorepo

If you are working inside the Fentaris repository and want a generated project to import the local `@fentaris/core` instead of the pinned range, pass a workspace or file reference to `--core-version`:

```bash theme={null}
fentaris init my-proxy --core-version workspace:*
```

or

```bash theme={null}
fentaris init my-proxy --core-version file:../packages/core
```

The doctor check skips installed-version validation for workspace and file references. Use your package manager to update released dependencies:

```bash theme={null}
pnpm update @fentaris/core
```

## Connect a Client

Point your MCP client to the endpoint printed by `fentaris dev`, usually:

```bash theme={null}
http://localhost:4000/mcp
```

Leave `fentaris dev` running. In a second terminal, initialize the MCP session and save the response headers:

```bash theme={null}
curl -sS -D headers.txt -o initialize.json -X POST http://127.0.0.1:4000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"curl","version":"1"}}}'
```

Capture the `mcp-session-id` header from the initialize response:

```bash theme={null}
SESSION_ID="$(grep -i '^mcp-session-id:' headers.txt | tr -d '\r' | cut -d' ' -f2)"
```

Send the MCP initialized notification on the same session:

```bash theme={null}
curl -sS -X POST http://127.0.0.1:4000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "mcp-session-id: $SESSION_ID" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}'
```

Then list tools with the same `mcp-session-id` header:

```bash theme={null}
curl -sS -X POST http://127.0.0.1:4000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "mcp-session-id: $SESSION_ID" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

## Call the First Tool

Call one tool returned by `tools/list` on the same session:

```bash theme={null}
curl -sS -X POST http://127.0.0.1:4000/mcp \
  -H 'Content-Type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -H "mcp-session-id: $SESSION_ID" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"specification__search","arguments":{"query":"accessibility","limit":1}}}'
```

The result should contain a successful MCP tool response. If `specification__search` is absent, verify outbound access to the generated upstream and rerun `tools/list`.

<Tip>
  You can also use `npx @modelcontextprotocol/inspector` and point it at `http://127.0.0.1:4000/mcp`.
</Tip>

For client-specific JSON snippets, see [Client Configs](/guides/client-configs).

## Replace the Development Policy

The generated `Policy.allowAll()` is only for the first local run. Replace the import and `fentaris(...)` declaration in `src/index.ts` with an explicit allow-list before sharing the proxy:

```ts theme={null}
import { fentaris, policy, streamableHttp } from "@fentaris/core";

const app = fentaris({
  policy: policy("quickstart")
    .mcp("specification")
    .allow("search"),
});
```

Keep the generated `app.mcp("specification", ...)` block, restart `fentaris dev`, and initialize a new MCP session. `tools/list` should now expose only `specification__search`; a direct call to another `specification__*` tool should return `not-permitted`.

## Add a Local Edge Device

<Warning>
  Edge is an alpha/preview surface. Validate service lifecycle and recovery on every target operating system before rollout. Protocol, CLI, and local state formats may change before a stable release, and the local control-plane mode is not a production multi-instance deployment.
</Warning>

Enable the disabled-by-default `edge.controlPlane` block in `fentaris.json`, set `publicOrigin` to `http://127.0.0.1:4000`, and restart the app. In one terminal join the device:

```bash theme={null}
npx @fentaris/edge join http://127.0.0.1:4000/_fentaris/edge --name "My laptop"
```

In the project terminal approve the displayed code for an application subject:

```bash theme={null}
fentaris edge approve ABCD-EFGH --subject alice
```

The running app enrolls the device, derives its assignments from your Edge targets and placements, and publishes capabilities after local setup and readiness succeed. See [Set Up an Edge Device](/guides/edge-device) for workload declarations and production guidance.

## Validate the Project

Run the local checks before connecting a client:

```bash theme={null}
fentaris check --offline
```

With `fentaris dev` still running, verify the full runtime from the second terminal:

```bash theme={null}
fentaris doctor --runtime
```

The final runtime check should report that MCP initialize responded at the configured endpoint. If it fails, follow the printed hint and [Troubleshooting](/troubleshooting) before connecting a client.
