Fentaris sits in front of upstream MCP servers and exposes one client-facing MCP endpoint with routing, policy, auth, and observability built in.

## When to Use Fentaris

- You run multiple MCP servers and want a single entrypoint.
- You need per-user policy or auditing without changing existing servers.
- You want structured logs and consistent naming across tools.

## Core Concepts

### `fentaris(...)`

Creates the proxy runtime from a high-level config object.

```ts theme={null}
const proxy = fentaris({
  servers: [mcp("filesystem", { transport: stdio({ command: "npx" }) })],
  port: 4000,
  path: "/mcp",
});
```

### `mcp(...)`

Declares an upstream MCP server. The server name becomes the prefix for proxied tools.

### `stdio(...)` and `streamableHttp(...)`

Declare how Fentaris connects to upstream MCP servers.

### Middleware and Routes

Use `proxy.use(...)`, `proxy.tool(...)`, and `proxy.mcp(name)` to add policy, logging, validation, and server-scoped behavior.

## Architecture

```mermaid
flowchart LR
  Client[MCP Client] --> Proxy["fentaris(...) proxy"]
  Proxy --> ServerA["mcp(\"filesystem\")"]
  Proxy --> ServerB["mcp(\"custom\")"]
```

## Tool Naming

Fentaris prefixes tool names to avoid collisions. Each tool becomes `server__tool`, and the displayed title includes the server `displayName`.

## Low-Level API

The underlying classes `McpProxy`, `McpServer`, and transport classes remain public for advanced integrations. New applications should start with `fentaris(...)`, `mcp(...)`, and transport helpers.

## What You Will Do Next

1. Declare upstream servers with `mcp(...)`.
2. Create the proxy with `fentaris(...)`.
3. Start the HTTP endpoint and connect your MCP client.
