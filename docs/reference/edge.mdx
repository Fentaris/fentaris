Use these APIs to declare governed edge placement and replace reference single-process infrastructure in managed deployments.

## Quick Start

```ts theme={null}
import { edge, runtime, stdio } from "@fentaris/core";

app.mcp("custom", {
  transport: stdio({
    command: "custom-server",
    args: ["--workspace", runtime.input("workspace")],
    env: { API_TOKEN: runtime.secret("token") },
  }),
});

app.mcp("custom").setup({
  workspace: edge.folder({ access: "read-write" }),
  token: edge.secret(),
});
```

## Targets and Selectors

### `app.target(name, target)`

Registers a reusable logical target. `cloud` is built in and reserved.

### `edge(options)`

Creates an edge target with a device selector and optional pool strategy.

Selectors:

* `edge.sessionDevice()`
* `edge.userDefaultDevice()`
* `edge.namedDevice(alias)`
* `edge.pool(name)`
* `selector.or(fallback)`

Pool strategies are `least-loaded`, `round-robin`, and `random`.

### `.target(name)`

Available on global, group, and user MCP handles:

```ts theme={null}
app.mcp("custom").target("cloud");
app.group("developers").mcp("custom").target("personal");
app.user("alice").mcp("custom").target("personal");
```

`app.user(id)` records subject-scoped configuration. It does not create or authenticate an identity.

## Runtime Inputs and Setup

Use `runtime.input(name)` for local/scalar values and `runtime.secret(name)` for secrets.

Setup builders:

* `edge.folder({ access })`
* `edge.file({ access })`
* `edge.secret()`
* `edge.string()`
* `edge.boolean()`
* `edge.number({ min, max })`
* `edge.select({ options })`

Cloud execution rejects unresolved runtime tokens with `EDGE_UNRESOLVED_RUNTIME_INPUT`. `StdioTransportOptions.runtimeValues` can provide explicit cloud-side string values.

## Managed Installation

### `edge.npm(options)`

Compiles a data-only install plan for `StdioTransportOptions.install`:

```ts theme={null}
app.mcp("custom", {
  transport: stdio({
    command: "custom-server",
    install: edge.npm({
      package: "@scope/custom-server",
      version: "1.4.2",
      bin: "custom-server",
      integrity: "sha512-...",
      registryUrl: "https://npm.example.com",
    }),
  }),
});
```

`package` must be a valid registry name and `version` an exact version; ranges and dist-tags are rejected. `bin` defaults to the unscoped package name and must be a bare executable name. `registryUrl` must use `https` except for loopback development. The compiled plan carries a `digest` and is included in the launch-recipe digest.

Related exports: `EdgeInstallPlan`, `compileEdgeNpmInstallPlan`, `validateEdgeInstallPlan`, `edgeInstallPackageId`, `edgeInstallDirectoryName`, and `StdioTransport.requiresManagedInstall()`.

When an install plan is present, `command` is resolved inside the device install directory. Cloud placement fails with `EDGE_UNRESOLVED_RUNTIME_INPUT`.

### Readiness and reporting

`EdgeDeploymentReadinessStatus` includes `install-required`. Reason categories are `install-pending`, `install-failed`, `install-denied`, and `install-verification-failed` (`EDGE_INSTALL_REASON_CATEGORIES`). The setup-status message carries an optional `EdgeInstallStatusReport` with the package identifier, install digest, resolved version, and reason category; `validateEdgeInstallStatusReport(...)` bounds it. Local install directories, caches, and package-manager output stay on the device.

## Core Runtime Adapters

`McpProxyOptions.edge` accepts:

* `deviceResolver`
* `sessionBindingStore`
* `sessionBindingExpiry`
* `sessionBindingListener`
* `transport`
* `capabilityCache`
* `telemetry`
* `sessionSelectionStore`
* `childBindingManager`
* `control`

Reference implementations include `EdgeTransport`, `EdgeWebSocketGateway`, `InMemorySessionBindingStore`, control-plane stores, and `EdgeCapabilityCache`.

<Warning>
  In-memory stores and the gateway active-socket map are single-process references. Multi-instance deployments require shared session bindings, device/desired/setup/manifest stores, and a distributed `EdgeChannelBroker`.
</Warning>

### Edge Control configuration

`edge.control` is explicit opt-in configuration. It requires the policy-filtered `EdgeInventoryService` and `EdgeSessionSelectionService` used by the control plane.

```ts theme={null}
const proxy = new McpProxy({
  policy: policy("agents")
    .mcp("edge").allow("list")
    .mcp("edge").allow("get")
    .mcp("edge").allow("select")
    .mcp("edge").allow("call")
    .mcp("edge").allow("call_many"),
  edge: {
    transport: edgeTransport,
    sessionSelectionStore,
    childBindingManager,
    control: {
      enabled: true,
      inventory,
      selections,
      defaultTargetName: "personal",
      limits: {
        maxDevices: 8,
        maxConcurrency: 4,
        maxDeadlineMs: 120000,
        maxSelectorCandidates: 100,
        maxChildBytes: 1000000,
        maxAggregateBytes: 4000000,
      },
    },
  },
});
```

The namespace `edge` is reserved. Individual tools remain hidden or denied unless effective policy allows them.

### Edge Control result contracts

Discovery uses public `{ name, inventoryVersion }` references. `edge__call` returns the selected public device, a server-generated correlation ID, a terminal status, and the sanitized MCP result. `edge__call_many` returns stable counts and exactly one `succeeded`, `failed`, `cancelled`, or `not-started` entry per resolved device.

Explicit input order is preserved. Declarative results are ordered by normalized public name. User limits can only reduce configured limits.

## Agent APIs

`@fentaris/edge` exports:

* `EdgeAgent` and `EdgeEnrollmentService`
* `LocalSetupManager` and `TerminalSetupProvider`
* `EdgeWorkloadSupervisor`
* `ExecutableAllowlistPolicy`
* `ManagedInstallManager` and `NodeEdgeInstallCommandRunner`
* platform, credential, process, and connection adapter contracts

The initial process model is one local MCP process/client per `{ deployment, downstream session }`.

`ManagedInstallManager` owns the pinned-package lifecycle: it evaluates the package allowlist through `EdgeWorkloadPolicy.allowInstall`, installs into `<data dir>/installs`, verifies before promotion, reuses an install across deployments and restarts, applies a bounded attempt budget, and prunes unreferenced installs. Replace `EdgeInstallCommandRunner` to control how the package manager is invoked.

## Protocol Compatibility

`EDGE_PROTOCOL_VERSION` is `2`; `EDGE_MCP_ENVELOPE_VERSION` remains `1`. Hello negotiates the highest mutually supported protocol version. Version 1 agents retain transparent Edge execution, while version 2 adds bounded observed facts, capacity, load, readiness, and orchestration correlation. Every accepted connection is bound to tenant, edge node, credential, protocol version, and a monotonically increasing connection generation.

Messages cover hello, heartbeat, desired state, setup status, capability manifests, lifecycle, MCP requests/results/errors, and cancellation.

Servers must reject routing claims that do not match server-side device, deployment, subject, target, and session state.

| Agent | Transparent execution | Presence and facts | Agent-native orchestration |
| --- | --- | --- | --- |
| Protocol v1 | Supported | Legacy heartbeat only | Not eligible for v2 fact/readiness selectors |
| Protocol v2 | Supported | Bounded facts, capacity, load, freshness, readiness | Supported when Edge Control is enabled and policy allows it |

Roll out the control plane first, then proxies, then upgrade agents. The gateway negotiates the highest mutual version, so v1 and v2 agents can coexist. To roll back, disable `edge.control` and new selectors first; transparent v1/v2 routing continues. Do not downgrade stored identity or inventory versions during rollback.

The `fentaris-edge` compatibility commands remain available during the migration window and map to the new services with warnings. New automation should use `fentaris edge`. A future major release may remove the legacy command names after a documented deprecation period.

Stateful failover and automatic mutation retry are not supported. Lost non-idempotent calls are reported as indeterminate and are never automatically replayed.

## Events and Health

`EdgeTelemetry` emits structured redacted events for target resolution, session binding, connection generations, desired-state reconciliation, setup, workloads, request duration, timeout, cancellation, failure, and parent/child orchestration lifecycle.

`edgeHealth(...)` adds checks for gateway, target resolution, device/pool availability, deployment readiness, capability cache age, inventory stores, presence expiry, selections, child cleanup, distributed routing, protocol distribution, and stale readiness.

Sensitive metadata is removed by `redactEdgeProtocolValue(...)` before telemetry reaches its sink. `serializeEdgePublicValue(...)` additionally bounds depth, collection size, string length, circular references, and encoded bytes.

Managed adapters can implement `EdgePoolSelectionStore` and `EdgeResultCorrelationStore`. Use `diagnoseEdgeProductionAdapters(...)` before production rollout. `EDGE_DISTRIBUTED_CONSISTENCY_REQUIREMENTS` documents the required compare-and-set, atomic-take, expiry, pool-selection, and channel-delivery semantics.

## Agent CLI

```bash theme={null}
fentaris edge join https://fentaris.example --name "Mac Studio"
fentaris edge run
fentaris edge service restart
fentaris edge list --as user:alice --json
fentaris edge status
fentaris edge disconnect "Mac Studio" --yes
fentaris edge revoke "Mac Studio" --yes
```

There is no MCP add/configuration command. Definitions and assignments remain controlled by Fentaris.
