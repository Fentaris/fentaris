> Configure structured logging for Fentaris proxies and middleware.

Use the default logger with `autoLog` first. Add a custom driver when logs need to go to a dedicated pipeline.

## Quick Start

Pass logging options through the high-level proxy declaration.

```ts theme={null}
import { fentaris, mcp, stdio } from "@fentaris/core";

const proxy = fentaris({
  servers: [
    mcp("filesystem", {
      transport: stdio({
        command: "npx",
        args: ["-y", "@modelcontextprotocol/server-filesystem", "/srv/shared"],
      }),
    }),
  ],
  autoLog: true,
});
```

Fentaris exposes the request logger as `ctx.log` in middleware, server routes, tool routes, operation routes, and lifecycle events.

## Add Tags And Metadata

Tags are indexed fields that should stay stable across a request. Metadata is detail for one log entry.

```ts theme={null}
proxy.use(async (ctx, next) => {
  ctx.log.setTag("traceId", ctx.transport.requestId ?? "no-trace");
  ctx.log.setTag("tenantId", String(ctx.subject?.tenant?.id ?? "unknown"));
  ctx.log.setTag("subject", ctx.subject?.id ?? "anonymous");

  ctx.log.info("request.received", {
    transport: ctx.transport?.type,
  });

  return next();
});
```

<Tip>
  Keep tags short and consistent. Prefer `traceId`, `tenantId`, `subject`, `server`, and `tool` over free-form labels.
</Tip>

## Logging Levels

Use levels consistently so alerts and dashboards stay predictable.

```ts theme={null}
ctx.log.debug("tool.input", { tool: ctx.tool?.proxyName });
ctx.log.info("tool.call", { tool: ctx.tool?.proxyName });
ctx.log.warn("tool.deny", { reason: "policy" });
ctx.log.error("tool.error", { message: "upstream failed" });
```

- `debug`: noisy diagnostics for development.
- `info`: normal operations such as routing and successful calls.
- `warn`: recoverable issues and policy denies.
- `error`: failures that need attention.

## Use A Custom Driver

Create a `Logger` when you want to forward entries to an external logging pipeline.

```ts theme={null}
import { Logger, fentaris, mcp, stdio } from "@fentaris/core";

const logger = new Logger({
  driver: {
    write(entry) {
      sendToLogPipeline({
        level: entry.level,
        message: entry.message,
        tags: entry.tags,
        metadata: entry.metadata,
        timestamp: entry.timestamp,
      });
    },
  },
});

const proxy = fentaris({
  logger,
  autoLog: true,
  servers: [
    mcp("github", {
      transport: stdio({ command: "github-mcp-server" }),
    }),
  ],
});
```

The driver must implement `write(entry)`. It can write JSON lines, forward to a vendor SDK, or fan out to logs and metrics.

## Logger Entry Shape

Drivers receive structured entries with a stable shape.

```ts theme={null}
type LogEntry = {
  level: "debug" | "info" | "warn" | "error";
  message: string;
  metadata?: Record<string, unknown>;
  tags?: Record<string, string>;
  timestamp: string;
};
```

Use this structure for querying, retention policies, and alert rules.

## JSON Lines Driver

Write one JSON object per line when your runtime already collects stdout.

```ts theme={null}
const logger = new Logger({
  driver: {
    write(entry) {
      process.stdout.write(`${JSON.stringify(entry)}\n`);
    },
  },
});
```

## Redis Driver

Use `RedisLoggerDriver` when you want Fentaris to append structured log entries to a Redis list.

```ts theme={null}
import { Logger, RedisLoggerDriver, fentaris, mcp, stdio } from "@fentaris/core";

const logger = new Logger({
  driver: new RedisLoggerDriver({
    client: redis,
    key: "fentaris:logs",
  }),
});

const proxy = fentaris({
  logger,
  servers: [
    mcp("github", {
      transport: stdio({ command: "github-mcp-server" }),
    }),
  ],
});
```

## Lifecycle Events

Use lifecycle events for operation-specific logs that should run after Fentaris knows the outcome.

```ts theme={null}
proxy.on("tool:success", async ({ ctx, durationMs }) => {
  ctx.log.info("tool.success", {
    server: ctx.tool?.serverName,
    tool: ctx.tool?.proxyName,
    durationMs,
  });
});

proxy.on("resource:success", async ({ ctx, durationMs }) => {
  ctx.log.info("resource.success", {
    uri: ctx.resource?.uri,
    durationMs,
  });
});
```

Fentaris enriches logs with safe metadata such as operation, subject id, server name, tool name, proxied tool name, resource URI, prompt name, completion target, transport type, session id, credential source, and policy outcome where available.

## Error Handling

When middleware catches an error, log a stable message and return a safe denial message.

```ts theme={null}
proxy.use(async (ctx, next) => {
  try {
    return await next();
  } catch (error) {
    ctx.log.error("tool.error", {
      message: error instanceof Error ? error.message : String(error),
    });

    return ctx.deny("Tool failed. Try again later.");
  }
});
```

<Warning>
  Do not log raw payloads, API keys, bearer tokens, decrypted credentials, or environment secret values.
</Warning>
