---
title: "OAuth 2.1"
description: "Authenticate MCP clients with an external issuer and manage named upstream OAuth accounts."
---

Declare `auth: oauth()` on an upstream MCP server and Fentaris performs the OAuth 2.1 client side for you: metadata discovery, dynamic client registration, PKCE, token exchange, refresh, and account-scoped token storage. Legacy per-user authorizations remain supported by the SDK and require explicit migration for named-account CLI use.

## Quick Start

```ts theme={null}
import { fentaris, mcp, oauth, streamableHttp } from "@fentaris/core";

const app = fentaris({
  servers: [
    mcp("linear", {
      transport: streamableHttp({ url: "https://mcp.linear.app/mcp" }),
      accounts: { work: { auth: oauth() } },
    }),
  ],
  oauth: { publicUrl: "https://proxy.example.com" },
});

await app.start();
```

```bash theme={null}
export FENTARIS_AUTH_KEY="<project-encryption-key>"
fentaris mcp auth connect linear --account work
fentaris mcp auth get linear --account work
```

Runtime selects the account independently of the downstream identity: `{ id: "assistant", upstreamAccounts: { linear: "work" } }`. A single configured account may be inferred; multiple accounts require an explicit choice.

## Four Ways to Declare It

### `oauth()`

Zero configuration. Fentaris discovers the protected resource and authorization server, registers a client dynamically (RFC 7591), uses PKCE with `S256`, and stores one authorization per named account. Servers without named accounts retain legacy per-user SDK behavior.

### `oauth({ clientId, clientSecret, scopes })`

Pre-registered client. Fentaris skips dynamic registration and authenticates to the token endpoint with the strongest method the authorization server supports. `clientSecret` accepts a literal string or `credential("...")`; a named-account credential reference resolves through the project vault or `defaults.credentials`. Legacy scoped OAuth requires an application default declaration; group/user credentials are never implicitly used as client secrets.

```ts theme={null}
mcp("github", {
  transport: streamableHttp({ url: "https://api.githubcopilot.com/mcp/" }),
  auth: oauth({ clientId: "Iv1.abc", clientSecret: credential("github.oauth.secret"), scopes: ["repo"] }),
})
```

### `oauth.clientCredentials({ clientId, clientSecret, scopes })`

Machine-to-machine access. No redirect and no human: Fentaris fetches a token directly and every caller shares it.

### `oauth({ provider })`

Escape hatch. The factory receives `{ server, user, session, store, redirectUrl }` and returns an MCP SDK `OAuthClientProvider` that Fentaris binds to that user's transport.

## Options

### `tokens`

`"per-user"` (default for the authorization-code grant) isolates one authorization per Fentaris user. `"shared"` reuses the first completed authorization for every caller. Unauthenticated callers always collapse to the shared session, so a personal single-user proxy works with no identity configuration.

### `registration`

Inferred from your declaration: `"dynamic"` with no `clientId`, `"preregistered"` with one, `"metadata-url"` when `clientMetadataUrl` is set. Set it explicitly to force one mode.

### `oauth.publicUrl`

Externally reachable base URL of the proxy. Required behind a reverse proxy or any non-loopback deployment, because the authorization server redirects the browser to `<publicUrl><callbackPath>`. When unset, Fentaris derives the callback from the bound listener.

### `oauth.callbackPath`

Path of the hosted redirect route. Defaults to `/_fentaris/oauth/callback`. Validation rejects a path that overlaps the MCP path or the Edge control-plane base path.

### `oauth.store`

Any object implementing `get`, `set`, `delete`, and `list`. Defaults to the encrypted local store when a key is available, otherwise an in-memory store.

### `oauth.consentTimeoutMs`

How long a tool call waits for the human to finish consent. Defaults to `90000`, below the usual MCP client request timeout. On timeout the call returns a "pending, retry" result instead of hanging.

### `oauth.agentTools`

Set to `false` to skip registering the built-in `fentaris__auth_status` and `fentaris__auth_login` tools. When group policies are enabled, grant access to these tools through the reserved `fentaris` namespace:

```ts theme={null}
const supportPolicy = policy("support")
  .allow("linear", "*")
  .allow("fentaris", "auth_status")
  .allow("fentaris", "auth_login");
```

## How Consent Reaches the Human

1. A tool call needs an authorization that does not exist yet.
2. If the connected MCP client supports URL-mode elicitation, Fentaris sends it the authorization URL and waits.
3. The human signs in; the authorization server redirects to the Fentaris callback; Fentaris exchanges the code and notifies the client.
4. Fentaris retries the original tool call once and returns its real result.

Clients that cannot elicit a URL get a structured error result instead:

```json theme={null}
{
  "code": "FENTARIS_OAUTH_AUTHORIZATION_REQUIRED",
  "server": "linear",
  "authorizationUrl": "https://auth.example.com/authorize?...",
  "expiresAt": "2026-01-01T00:10:00.000Z"
}
```

<Note>
  `tools/list` never contacts an authorization server. An upstream that still needs a login contributes no tools instead of failing the whole listing, and the built-in `fentaris__auth_*` tools tell the agent why.
</Note>

## Token Store

Named-account tokens, client registrations, and discovery metadata are lifecycle records in the shared encrypted project vault under `fentaris.internal.oauth.<encoded-server>.<encoded-account>`. They are omitted from ordinary secret listings and never exposed by MCP JSON output. On the standalone branch this uses the existing encrypted credential backend; the ProjectVault facade is used when integrated. Legacy scoped records remain in `<authDir>/oauth-tokens.enc.json` and are never automatically reassigned.

The runtime reads the same vault references as the CLI, so refreshes persist automatically. A headless transport can refresh stored authorization without a callback URL; a callback is required only for a new authorization-code flow. Supply `FENTARIS_VAULT_UNLOCK_KEY`, the existing `FENTARIS_AUTH_KEY`, or an explicit `oauth.store`. MCP connect does not silently create a key. Without durable credentials, SDK OAuth uses an ephemeral store and reports a configuration warning.

## CLI

```bash theme={null}
fentaris mcp auth connect linear --account work
fentaris mcp auth connect linear --account work --print-url --non-interactive
fentaris mcp auth connect github --account work --port 8976
fentaris mcp auth get linear --account work
fentaris mcp auth connect linear --account work --reauth
fentaris mcp auth disconnect linear --account work
```

Connect opens a loopback browser flow or prints the URL to stderr when explicitly requested. JSON and noninteractive flows do not open a browser; authorization-code flows require `--print-url`. OAuth `--timeout` is in milliseconds (300000 by default). Existing authorization is preserved until `--reauth` succeeds; cancellation closes the listener and leaves the connection unchanged.

Disconnect clears only the selected account, attempts remote revocation if the provider advertises an endpoint, and reports its outcome. Shared credential values are preserved. To migrate a legacy session, explicitly run `fentaris mcp auth migrate linear --account work --from-session user:alice`; the source is retained for rollback. Legacy `shared` and `user:` namespaces remain distinct from `account:` sessions.

## Network Guardrails

Every authorization-server request — discovery, registration, token, revocation — passes the same guardrails as the upstream MCP URL. A private, loopback, or link-local authorization server is refused unless the transport allows it:

```ts theme={null}
streamableHttp({ url: "http://127.0.0.1:4001/mcp", network: { allowPrivateNetworkUrls: true } })
```

## Troubleshooting

### The browser lands on a "not found" page after signing in

The authorization server redirected to a callback the proxy does not host. Set `oauth.publicUrl` to the externally reachable base URL and confirm `oauth.callbackPath`.

### The tool call returns "Authorization is still pending"

Consent did not complete within `consentTimeoutMs`. Sign in, then call the tool again; the stored tokens are used immediately.

### `FENTARIS_CONFIG_OAUTH_TRANSPORT_UNSUPPORTED`

`oauth()` only works on the native `streamableHttp()` and `sse()` upstream transports. A stdio server cannot carry an OAuth authorization.

### `FENTARIS_CONFIG_OAUTH_CLIENT_SECRET_UNRESOLVED`

The `credential(...)` reference used for `clientSecret` is not declared in app defaults, groups, or users. Declare it and store the value with `fentaris secrets set`.

### The upstream keeps asking for a new login

The refresh token was rejected or the authorization server invalidated the registered client. Run `fentaris mcp auth connect <MCP> --account <ACCOUNT> --reauth` to authorize that account again.

## Authenticate Inbound MCP Clients

Configure an external authorization server as the issuer. Fentaris validates its access tokens and serves RFC 9728 metadata; clients discover the issuer, sign in there, and send `Authorization: Bearer <token>` to Fentaris.

```ts theme={null}
import { fentaris, oauthIdentityStrategy, group, user, policy } from "@fentaris/core";

const app = fentaris({
  identity: oauthIdentityStrategy({
    issuer: "https://auth.example.com",
    resource: "https://proxy.example.com/mcp",
    scopes: ["mcp:tools"],
    mapUser: (claims) => ({ id: String(claims.email ?? claims.sub) }),
  }),
  groups: [group({
    id: "team",
    users: [user("alice@example.com")],
    policy: policy("team").allow("workspace", "*"),
  })],
});
app.local("workspace").tool("whoami", {
  description: "Show the authenticated user",
  inputSchema: { type: "object", properties: {} },
}, (ctx) => ({ content: [{ type: "text", text: ctx.user.id ?? "anonymous" }] }));
await app.start();
```

### Issuer, resource and scopes

`issuer` must exactly match the token's `iss`. `resource` must appear in `aud` (a string or array). Fentaris requires a finite `exp`, checks `nbf` when present, and allows 60 seconds of clock skew. Required `scopes` must all appear in the space-separated `scope` claim or `scp` array. Granted scopes are available in `ctx.identity.metadata.scopes`.

Set the externally visible `resource` behind a reverse proxy, including any public path prefix. If omitted, it defaults to `oauth.publicUrl` plus the MCP path, or the actual loopback listener URL in development. Non-loopback HTTP and URLs with credentials, query strings or fragments are rejected. OAuth identity requires authentication by default; an explicit `{ strategy, required: false }` makes identity optional.

### JWT signing keys

By default, Fentaris discovers `jwks_uri` through authorization-server metadata (RFC 8414), falling back to OpenID Connect discovery. It verifies RS256, PS256, ES256 and EdDSA (Ed25519) signatures with Node crypto. HS256 and encrypted JWTs are unsupported.

Use `jwks: { url: "https://auth.example.com/keys", cacheTtlMs: 300000 }` for an explicit endpoint. Keys are cached for five minutes by default. An unknown `kid` refreshes the JWKS once; cached keys remain usable during an endpoint outage, and requests without an available signing key fail closed.

### Metadata and bearer challenges

HTTP and SSE exposures serve public JSON at `/.well-known/oauth-protected-resource` and `/.well-known/oauth-protected-resource<mcpPath>` (the SSE path for SSE exposure). The document contains `resource`, `authorization_servers`, `bearer_methods_supported: ["header"]`, and configured `scopes_supported`.

Every OAuth 401 includes `WWW-Authenticate: Bearer resource_metadata="..."`. Failed verification adds `error="invalid_token"`; missing required scopes add `error="insufficient_scope"` and `scope`. Sessions stay bound to the authenticated user and strategy; presenting another user's token on an existing session returns 401.

Fentaris does not provide inbound authorization, token or client-registration endpoints. Configure those on your issuer.

### Opaque tokens and introspection

Provide `verify` to return trusted claims from your issuer's authenticated introspection endpoint. Fentaris still checks issuer, audience, expiry and scopes. Configure either `verify` or `jwks`.

```ts theme={null}
oauthIdentityStrategy({
  issuer: "https://auth.example.com",
  resource: "https://proxy.example.com/mcp",
  scopes: ["mcp:tools"],
  verify: async (token) => {
    const response = await fetch("https://auth.example.com/introspect", {
      method: "POST",
      headers: { Authorization: `Basic ${process.env.INTROSPECTION_BASIC_AUTH}` },
      body: new URLSearchParams({ token }),
      signal: AbortSignal.timeout(5000),
    });
    if (!response.ok) throw new Error("Introspection unavailable");
    const claims = await response.json();
    if (!claims.active) throw new Error("Inactive token");
    return claims;
  },
});
```

### User mapping and API-key fallback

The default user id is `claims.sub`. `mapUser` may synchronously or asynchronously map trusted claims to a declared Fentaris user. When groups are configured, mapped users must belong to one of them.

To keep API keys alongside OAuth, use an ordered strategy array. The first non-null identity wins; the first strategy exposing a challenge supplies OAuth discovery.

```ts theme={null}
import { apiKeyIdentityStrategy, oauthIdentityStrategy } from "@fentaris/core";

const app = fentaris({
  identity: [
    oauthIdentityStrategy({ issuer: "https://auth.example.com", resource: "https://proxy.example.com/mcp" }),
    apiKeyIdentityStrategy({ auth }), // your loaded FentarisAuth instance
  ],
});
```

## Verify OAuth Locally

The repository includes an opt-in mcpjam SDK suite and a campaign against packed packages:

```bash theme={null}
FENTARIS_MCPJAM=1 pnpm --filter @fentaris/core test test/conformance
pnpm test:oauth-verification
pnpm verify:oauth:practical
```

The campaign covers upstream DCR/elicitation, CLI login, client credentials, inbound DCR and pre-registered headless conformance, login with tool calls, and API-key fallback. Each attempt retains a requirement-mapped `REPORT.md`, command logs and tarball SHA-256 identities. Any failed or blocked scenario returns a non-zero exit code. See `scripts/oauth-verification/README.md` in the repository for candidate and attempt options.
